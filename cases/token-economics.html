01Measure first

I studied 480 of my own AI sessions to see where the tokens actually went. A small number of very long sessions drove more than half of all usage, and fixed start-up costs were paid again on every scheduled run.

02A token-diet playbook

I wrote a reusable playbook: find the fixed overhead, build a golden test before changing anything, measure one real run, then pull the cheapest levers first. On one real job it cut a ~155k-token request to ~11k with the same output quality.

03Route by tier

Cheap models do bulk and mechanical work, and the strongest model does judgment. Every plan ends in a state a smaller model can run, so the expensive model plans once and doesn't execute.

04Fetch, read and navigate are different jobs

Fetching data is free code. Reading is tiered: no model, then a small local model, then the strongest model only for samples. Navigation is engineered into the system rather than left to an agent wandering the web.

05Plain code before a model

Scheduled jobs check in plain code whether there is anything to do before a model wakes up. Data lives in local files and ledgers, so nothing is re-read across sessions.

06Tooling around it

I built add-ons that show context size and cost live, hide tools a project doesn't use, enforce workflow steps, and give one view of every running session and background job.
