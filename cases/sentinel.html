Sentinel: a central intelligence layer for buying signals

One system that watches many market sources, turns what it sees into a single picture of which accounts are worth approaching now, and feeds that to the outreach engine every day.

01The problem

Buying signals were scattered across feeds such as filings, tenders, deals, hiring and news. Each had its own format and its own idea of what counts as important, so nobody could see one ranked view of the market.

02Collection

Independent trackers each watch one kind of source on their own schedule. Each tracker has a freshness rule, so the daily queue is never fed stale data.

03Normalisation and merge

Every source is converted to one common signal shape and then grouped by account. An account rises when several independent sources point at it at once. Corroboration counts for more than any single headline.

04How priority is decided

Every signal is weighed on relevance, how actionable it is, how close the account already is to us and how recent it is. That sorts the market into Hot, Warm and Cold. An AI relevance check runs on top and defaults to "not relevant", and weak news can never be scored as hot, however good it sounds.

05Applied across four geographies

The same design runs for the EU, the GCC, India and the US. Each region adds its own sources, such as exchange disclosures, public tenders and regulatory deadlines, and produces its own morning brief. One architecture now serves four markets.

06Feeding outreach

Sentinel's output is the starting point for the daily outbound engine, and outcomes flow back to show which signal sources actually produce conversations.

Built to be token-efficient

  • Collection, merging and scoring are plain code and use no model tokens.
  • The model is called only where judgment is needed: is this signal really about this company?
  • Everything is stored locally, so nothing is re-read or re-fetched across sessions.
