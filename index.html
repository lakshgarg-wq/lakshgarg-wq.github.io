Agent-orchestrated outbound

A daily system that admits only accounts with a real reason to buy, ranks them, has agents research each one and draft a message, and gates every draft before it reaches me. I approve every send, and what I send feeds back into how the next drafts are written.

Outcome: a repeatable daily outbound loop, where agents do the work and a human owns the judgment.

Funnel analytics

Finding the real bottleneck

Weekly audits of the CRM against the outreach log, stage by stage, from invite to accepted, first message, follow-up and reply.

Outcome: the data showed the constraint was follow-up volume, not message quality. That moved build effort away from better copy and onto the accept-to-first-message stage.

Data sourcing · Entity matching

GrantScope: a deeptech account database

Nine Spanish and EU grant programmes scraped, matched across sources and tagged into a deeptech core. It is rebuilt monthly in about 12 minutes and used to build scouting shortlists for ecosystem events.

Outcome: shortlists that took days of manual searching now take minutes. The same pattern now runs for EU tenders, PE deal flow and export-import buyer discovery.

Case study →
Token economics

Making AI systems cheap enough to run every day

Measure first

I studied 480 of my own AI sessions to see where the tokens went. A handful of very long sessions turned out to drive most of the cost.

Cut what the model reads

I wrote a reusable token-diet playbook. On one real job it cut a ~155k-token request to ~11k, with the same output quality.

Route by tier

Cheap models do bulk work and the strongest model does judgment. Every plan ends in a state a smaller model can run.

Tooling around it

I built add-ons that show context size live, hide unused tools, enforce workflow steps and track every running session.
